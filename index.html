En la arquitectura actual de ese archivo HTML, toda la información se almacena única y exclusivamente de forma local en el navegador web de la persona que lo está usando, mediante IndexedDB. GitHub (o GitHub Pages) actúa únicamente como un servidor de archivos estáticos: entrega el código HTML, CSS y JavaScript a la pantalla, pero no posee una base de datos ni guarda información en sus servidores. ¿Qué implica que se guarde en IndexedDB? Aislamiento por usuario y equipo: Si tú cargas las 19,000 filas de Reebok o las 100,000 de Adidas en tu computadora, los datos se guardan en el disco duro de tu navegador. Si un encargado de marca abre el mismo enlace de GitHub en su computadora, verá la plataforma en blanco, porque su navegador no tiene acceso al almacenamiento local del tuyo. Persistencia y límites: IndexedDB es capaz de soportar cientos de miles de registros sin problemas de rendimiento. Sin embargo, si se limpian los datos de navegación (caché y almacenamiento del navegador) o se ingresa en modo incógnito, la base se reinicia a cero. Cómo volverlo multiusuario y centralizado Para que tú y los encargados de cada marca consulten y actualicen la misma información en tiempo real desde el enlace de GitHub, se debe enlazar el HTML con una base de datos en la nube: Firebase Realtime Database / Firestore: Es la alternativa más rápida y directa para un frontend estático en GitHub. Se inyecta la librería de Firebase en el del HTML y se vincula con tu proyecto en la nube (mediante las credenciales de Firebase que ya utilizas en proyectos como el de monitoreo de embarques). Cada vez que subas una compra inicial o cargues una OC con DROPs, la base se sincroniza de inmediato para cualquier usuario con el enlace.
